# Cybele Project Console (Team Web App)

The shared interface for the **Cybele AI Design Assistant** — a local web app that tracks the
project and **prepares + runs tasks** for each pipeline (PPTX, Whitepaper PDF, Blog visuals,
Architecture diagrams). It's the "Web App for the team" from the project vision.

Single self‑contained `index.html` + `brand-icons*.js`, served by `server.js` on **port 3491**.

## Run it

```bash
cd web-app
node server.js     # serves http://localhost:3491 — no dependencies, no npm install needed
```

The server uses only Node built‑ins (`http`, `fs`, `path`, `child_process`), so there is nothing to
install. (PDF preview thumbnails are rendered with `py -3` + PyMuPDF when available.)

On Windows you can also double‑click **`Start-Cybele-Console.bat`** — it starts the server (with
auto‑restart) and opens the browser. The server serves from its own folder, so it runs from any clone.

## What it does

- **Overview** — launch pipelines and see recent tasks; filter by project.
- **Pipelines** — pick one, upload a source document, write a prompt; the server loads the matching
  section of `data/progress.md` as context and saves a **task** (`jobs/<id>/`).
- **Task lifecycle** — `queued → ▶ Run with Claude → review / ✎ request changes (revisions) →
  ✓ approve & close`. **Preview** (embedded PDF) and **Download** (pick destination folder) per task.
- **Task history** — every task, grouped by type, read‑only.
- **Brand assets** — Cybele palette (06/26, primary `#0A74D6`), logos, and the 131 Cybfont icons.
  Colors and files are editable and persisted.
- **Content source (GitHub)** — `progress.md` and the brand (colors + assets) are mirrored from this
  repo into the local `data/` cache, so the whole team starts from the same source. The server pulls
  via `git` (reusing your existing git credentials — no token to manage), on startup and on demand
  (**Settings → Content source → Sync now**). Reads work offline from the cache; per‑instance state
  (`data/roadmap.json`, `jobs/`) is not synced. Config lives in `data/source.json` (gitignored);
  with no config it auto‑detects the clone you run from.
- **Settings** — language (English / Español), content‑source status, and console config.
- Dark/light Cybele theme, EN/ES i18n, responsive (hamburger menu on small screens).

## How tasks actually run

The app **prepares** the work; Claude (Claude Code) **executes** it. When you click **Run with
Claude** (or ask in a session: *"run task‑XXXX"*), Claude reads `jobs/<id>/job.json` and follows
[`RUNBOOK.md`](RUNBOOK.md) / [`CLAUDE.md`](CLAUDE.md): runs the pipeline, writes output to
`jobs/<id>/output/`, renders a PDF preview, and marks the task done.

## Key files

| File | Purpose |
|---|---|
| `index.html` | The whole UI (views, i18n, theme, task/brand logic) |
| `server.js` | Static server + endpoints: `/roadmap`, `/jobs`, `/jobs/<id>` (run/revise/approve), `/brand`, `/progress-section`, `/run(-stream)` |
| `brand-icons.js` / `brand-icon-lib.js` | Brand icons (pipeline + 131‑icon library), generated by `build-icons.js` / `build-icon-lib.js` |
| `data/` | `roadmap.json`, `brand.json`, `progress.md`, `brand-assets/` (seed + content) |
| `RUNBOOK.md` / `CLAUDE.md` | How Claude attends a queued task |

`node_modules/` and `jobs/` are git‑ignored (restored / generated locally).
